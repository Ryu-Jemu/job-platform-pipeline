# Notion 평가 기준 확인과 제출물 구성

2026-10-02 14:16 KST에 [실습 진행 가이드](https://traveling-goat-521.notion.site/3ecff449f16c8032a97dfb71432efbdc)를 확인했다. 공개 페이지의 `loadPageChunk` 응답을 두 청크로 끝까지 읽고, 다른 limit으로 다시 요청하여 평가표 11행(헤더 + 10항목)의 내용이 모두 일치함을 확인했다. 평가표 원문 프로퍼티의 SHA-256과 블록 ID는 [검증 기록](../reports/notion_rubric.json)에 남겼다.

원문 기준은 **10항목 × 10점, 총 100점**이며 각 항목은 우수 10점, 보완 8점, 미흡·미확인 6점이다. 아래는 원문을 요약한 표다. 실제 점수는 강사가 판단하며 이 문서는 점수를 확정하지 않는다.

| 번호 | 평가 내용 | 10점 요건 | 8점 상태 | 6점 상태 | 실행 증거 위치 |
|---|---|---|---|---|---|
| 1 | 동시 수집 | 병렬·비동기 요청 구현 | 동시 실행 확인 부족 | 순차 수집 또는 미구현 | ETL: 수집 코드와 동시성 검증 |
| 2 | 실패 재시도 | 백오프 등 자동 재시도 구현 | 대기 등 구조 미완성 | 재시도 없음 | ETL: 실패별 시도·대기 기록 |
| 3 | 데이터 적합성 | 분할 요청·고유키·집계 가능성을 모두 충족 | 일부 조건 불명확 | 조건 불충족으로 진행 불가 | ETL: 원천·키·집계 단위 |
| 4 | 원본·정제 저장 | 용도에 맞는 분리 저장 | 분리 목적 불명확 | 단일 구조에 혼합 저장 | ETL: DDL 또는 테이블 목록 |
| 5 | 멱등성 | 실제 재실행 행 수로 중복 없음 확인 | 방지 코드만 있고 비교 없음 | 중복 발생 | ETL: 두 번 적재한 전후 행 수 |
| 6 | 의미 있는 집계 | 목적을 설명한 집계 SQL | 집계 이유 누락 | 집계 없음·무의미 | EDA: 목적·SQL·결과 |
| 7 | 실제 데이터 시각화 | 수집 데이터 차트 | 샘플 숫자로 보이는 차트 | 차트 없음 | EDA: DB 조회 기반 그림 |
| 8 | 결측·분포 판단 | 수치와 원인 해석 문장 | 숫자만 있고 해석 없음 | 확인 없음 | EDA: 결측률·분포·해석 |
| 9 | 실행 결과 보존 | 코드와 실행 결과 보존 | 일부 결과 누락 | 코드만 있음 | ETL·EDA: 실행 출력 보존 |
| 10 | 자기 방식 | 데이터·구조·코드에 직접 만든 흔적 | 대부분 시연 그대로 | 시연을 그대로 실행 | ETL·EDA: 주제와 설계 근거 |

1번의 순차/동시 시간 비교는 선택이다. 5번은 `ON CONFLICT` 코드만으로 충족되지 않으며 실제 두 번 적재한 행 수가 필요하다. 6번은 쿼리의 목적, 8번은 결측·분포의 원인을 한 문장 이상 설명해야 한다. 원문은 결과를 지우지 않고 제출 직전 처음부터 끝까지 실행해 저장하도록 권장한다.

원문에서는 **결과 노트북 1개**를 명시한다. 이번 결과물은 최신 사용자 요청에 따라 **ETL 1개 + EDA 1개, 총 2개**로 구성한다. 원문의 제출 개수와 차이가 있다는 사실은 유지하며, 강사가 두 파일 제출을 허용했는지는 확인되지 않았다. 평가 증거를 위 표에 따라 두 파일에 배치하고 각 파일의 첫 셀에서 다른 파일을 연결한다.

Airflow와 Docker DAG 단계는 원문에서 선택이고 평가 대상이 아니다. 이 프로젝트에서는 기존 사용자 요구에 따라 운영 증거를 ETL에 유지한다. 원문에는 전체 소스를 `%%writefile` 셀로 복제해야 한다는 의무가 없으므로, 핵심 구현과 검증 근거를 남기고 패키지 전체 중복은 제거할 수 있다.

집계 쿼리와 차트는 각각 1개 이상이면 원문 최소 요건에 해당한다. 분석 개수를 늘려 점수를 높인다는 근거는 없다. 통계적으로 판단할 자료가 부족한 시계열·상관 분석은 한계를 적거나 제외하고, 실제 자료로 해석 가능한 직무·원천·기술·품질 분석을 남긴다. 이는 사용자 요구에 맞춘 구성 판단이며 원문의 별도 필수 조건은 아니다.
