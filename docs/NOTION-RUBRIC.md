# Notion 평가 기준 확인과 제출물 구성

2026-10-02 14:16 KST에 [실습 진행 가이드](https://traveling-goat-521.notion.site/3ecff449f16c8032a97dfb71432efbdc)를 확인했다. 공개 페이지의 `loadPageChunk` 응답을 두 청크로 끝까지 읽고, 다른 limit으로 다시 요청하여 평가표 11행(헤더 + 10항목)의 내용이 모두 일치함을 확인했다. 평가표 원문 프로퍼티의 SHA-256과 블록 ID는 [검증 기록](../reports/notion_rubric.json)에 남겼다.

원문 기준은 **10항목 × 10점, 총 100점**이며 각 항목은 우수 10점, 보완 8점, 미흡·미확인 6점이다. 아래는 원문을 요약한 표다. 실제 점수는 강사가 판단하며 이 문서는 점수를 확정하지 않는다.

| 번호 | 평가 내용 | 10점 요건 | 8점 상태 | 6점 상태 | 실행 증거 위치 |
|---|---|---|---|---|---|
| 1 | 동시 수집 | 병렬·비동기 요청 구현 | 동시 실행 확인 부족 | 순차 수집 또는 미구현 | ETL: 수집 코드와 동시성 검증 |
| 2 | 실패 재시도 | 백오프 등 자동 재시도 구현 | 대기 등 구조 미완성 | 재시도 없음 | ETL: 실패별 시도·대기 기록 |

1번의 순차/동시 시간 비교는 선택이다. 5번은 `ON CONFLICT` 코드만으로 충족되지 않으며 실제 두 번 적재한 행 수가 필요하다. 6번은 쿼리의 목적, 8번은 결측·분포의 원인을 한 문장 이상 설명해야 한다. 원문은 결과를 지우지 않고 제출 직전 처음부터 끝까지 실행해 저장하도록 권장한다.

원문에서는 **결과 노트북 1개**를 명시한다. 최신 사용자 요청에 따라 **통합본 1개를 기본 제출물**, 기존 ETL·EDA 두 파일을 보조 자료로 제공하여 제출 개수 조건을 충족했다. 통합본은 원본 두 파일의 코드 셀 21개를 ETL→EDA 순서로 그대로 가져와 **하나의 새 커널에서 실행했다**. 원본 파일 두 개의 실행 전후 SHA-256이 같고, 통합본의 코드 문자열·순서가 원본과 일치함을 확인했다.

- 보조 자료: [ETL 노트북](../job_platform_etl.ipynb), [EDA 노트북](../job_platform_eda.ipynb)
- 기존 검증 근거: [노트북 검증](../reports/notebook_validation.json), [ETL 검증](../reports/etl_validation.json), [SQL/pandas 검증](../reports/analysis_validation.json)

통합본의 ETL·EDA 분석 기준은 모두 **2026-10-02 16:20 KST**이고 보조 자료는 **14:40 KST** 그대로다. 기준 시각 차이 때문에 일부 수치가 다를 수 있다. 원본 두 파일을 갱신해 수치를 맞추지 않고 각각의 기준 시각을 유지했다. 평가에는 실행 결과의 저장·근거의 접근성·검증 성공을 사용한다.

직접 확인한 통합본은 코드 21개, 실행 번호 **1~21 연속**, **오류 출력 0개**, **PNG 그림 13개**, **해석 출력 16개**다. 동일 코드의 새 커널 실행과 결과 보존을 확인했다. 통합본의 절 앵커 19개가 실제로 존재하며, 아래 평가표의 로컬 파일·절 링크에서 누락된 대상은 0개다. 기존 분리본은 ETL 20셀 중 코드 11개, EDA 19셀 중 코드 10개다. 아래 ETL·EDA 실행 셀 번호는 보조 자료의 `execution_count`이며, EDA 실행 셀에 11을 더하면 통합본의 실행 번호다. 통합본의 16:20 KST 출력은 **부분 수집 자료**다. 노트북 구성·검증의 완료와 하루 관측의 완료는 구분한다.

통합본에서 10개 항목의 우수 요건에 대응하는 구현과 실행 근거를 확인했다. P0 제출 통합과 P1 근거 접근성·시험 의미·출력 보존은 완료했다. 하루 관측은 20:00 최종 실행을 기다리고 있으며, 현재 부분 자료라는 상태를 노트북에 명시했다. P2 확장은 선택 사항이다. 최종 공식 점수는 평가자가 판단한다.

Airflow와 Docker DAG 단계는 원문에서 선택이고 평가 대상이 아니다. 이 프로젝트에서는 기존 사용자 요구에 따라 운영 증거를 ETL에 유지한다. 원문에는 전체 소스를 `%%writefile` 셀로 복제해야 한다는 의무가 없으므로, 핵심 구현과 검증 근거를 남기고 패키지 전체 중복은 제거할 수 있다.

집계 쿼리와 차트는 각각 1개 이상이면 원문 최소 요건에 해당한다. 분석 개수를 늘려 점수를 높인다는 근거는 없다. 통계적으로 판단할 자료가 부족한 시계열·상관 분석은 한계를 적거나 제외하고, 실제 자료로 해석 가능한 직무·원천·기술·품질 분석을 남긴다. 이는 사용자 요구에 맞춘 구성 판단이며 원문의 별도 필수 조건은 아니다.
